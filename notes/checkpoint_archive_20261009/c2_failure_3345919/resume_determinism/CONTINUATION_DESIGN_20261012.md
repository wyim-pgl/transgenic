## Decision

Use one new, small host Python3.6 standard-library controller, one immutable configuration manifest, one locked durable journal, and a reviewed production allocation helper. Adopt the already submitted initial proof3369338 by its submission receipt; never submit it again. The new controller submits validation400 only after strict initial-proof acceptance, promotes validation's verified **resumed410** output by receipt-bound relocation, and submits one production link at a time through4099. Keep at400, both comparison outputs, original200, and diagnostic256 as evidence.

This is preferable to a prequeued dependency chain: Slurm dependencies cannot enforce the receipts, checkpoint health, quota, or final evaluation gates between links. An external workflow service would add an unnecessary dependency. The host controller does no training, tensor loading, corpus hashing, or checkpoint copying. Such work runs in allocations; login work is limited to small manifests, source/helper files, scheduler metadata, and quota queries.

The old `continue_c2.py` and controller3276938 are historical evidence only. Never import/execute it, reuse its journal, revive its process, or remove its blocked state. Start a distinct operation directory, for example `ops/c2_continuation_20261012/<operation-id>/`, and store its identity in every receipt/comment. The pinned source is parameterized and checked against proof receipts, not silently defaulted to d7b1a37 or even188bf3e.

## Configuration and receipt contract

CLI proposal (new program name `continue_c2_history.py`):

```text
python3 continue_c2_history.py init --config CONFIG.json --state-dir NEW_DIRECTORY
python3 continue_c2_history.py tick --state-dir DIRECTORY
python3 continue_c2_history.py watch --state-dir DIRECTORY --poll-seconds 60
python3 continue_c2_history.py status --state-dir DIRECTORY
python3 continue_c2_history.py reconcile --state-dir DIRECTORY
```

`init` is exclusive and refuses an existing journal; all subsequent invocations deliberately resume only that new controller schema. `status` is read-only. `tick` performs at most one durable mutation transition. `watch` repeats tick, logs a concise transition, and can be restarted safely. `reconcile` observes an uncertain action; it never blindly resubmits. No general shell hook, arbitrary automatic retry, or `--force` bypass.

Config must explicitly contain operation UUID, owner name/UID, WORK/SCRATCH/SIF and container mapping, expected project22169/ddn_ssd, canonical/original-backup/candidate/proof/validation/diagnostic paths, source commit, snapshot commit, source directory and manifest SHA, helper directories/manifests for each phase, existing proof job3369338 and submission/staging receipt digests, bindings/config digests, target4099,4GPUs/seed123/batch1/bf16/deterministic, cache contract, held obsolete job3345920, protected B5/B6 IDs, and permitted partitions/resources. ## Duplicate-safe submission and uncertain recovery

Use a unique deterministic token per phase/link, e.g. `c2-<operation-short>-val-0001` or `c2-<operation-short>-prod-0001`, in Slurm `--comment` and a bounded job-name. One controller lock protects the operation; a second shared canonical-C2 lock protects promotion/submission across operation directories. Search all live owner jobs plus accounting since intent creation for matching token **and** any foreign job targeting the canonical C2 path. Refuse duplicate/foreign active writers. Slurm comments are discovery metadata, not idempotency keys.

Before `sbatch`, save/fsync intent containing token, exact argv/env allowlist SHA, source/helper/receipt pins, predecessor, index, and start time. Execute once with `subprocess.run` argv, bounded timeout, `universal_newlines=True`, no shell. Save stdout/stderr/return code and parsed `jobid[;cluster]`; then fsync `submitted`. Use Python3.6 APIs: no `capture_output`, `text=`, dataclasses, `shlex.join`, or modern pathlib conveniences. If shell transport is unavoidable, join individually `shlex.quote`d arguments; preferably run controller on dtai itself.

Crash/timeout after intent is **uncertain even if no ID was received**. Reconcile scheduler by token+owner+time+command/source. Exactly one matching job can be adopted with evidence and logged ID; two matches block. No matches can reflect accounting delay or accepted-but-not-visible submission, so keep blocked/observing rather than submit again. Only definitive independently recorded nonacceptance permits creating a new attempt. A new process must not infer permission from elapsed time or an empty queue. Normal Priority wait is not a failure. Do not prequeue two production jobs: submit the next only after predecessor state and output checkpoint receipts pass.
