## Material findings

1. **P2 — Markdown links can become false EXTRACTED references.** In `transgenic_graphify_finish.py:24–37`, Markdown links and inline-code strings share the same two-candidate resolver: both repository-relative and document-relative paths are considered. A Markdown relative URL has a defined document-relative base; existence of a same-named root file does not establish that target. A focused execution of only the two pure reference helper functions reproduced `notes/wait_work_20260916/repro/captured/resume.md:L15`, `[quarantine.md §1n](quarantine.md)`, producing an EXTRACTED 1.0 edge to repository-root `quarantine.md`. The actual document-relative target does not exist. Root `quarantine.md` and `.atl/quarantine.md` are distinct regular files with different hashes. The available corpus has 15 such root-only Markdown occurrences, mostly archived handoffs. This converts broken or relocated historical links into asserted links to a different document. **Fix:** resolve Markdown relative URLs only against their source document, retaining an unresolved historical link as unresolved. Treat explicitly root-relative inline-code paths separately; do not promote an existence-based fallback for Markdown to an exact fact.

2. **P2 — Final graph export discards distinct relationships sharing a node pair.** `transgenic_graphify_finish.py:120–123` builds an undirected simple graph and calls `to_json` without `original_links`; the labels path at lines 139–140 does the same. The installed `build_from_json` creates `nx.Graph` (`graphify/build.py:1319`) and explicitly retains only one edge per pair (`:1734–1775`). The currently published input chunks, AST and fallbacks already contain **659 valid-endpoint node pairs with multiple distinct relations**, excluding unfinished chunks 1 and 65 and without adding literal bridges. For example `figures_make_figure3_original_spearman` → `figures_make_figure3_original_spearman_rank` has both `calls` and `contains`. Only one can survive ordinary graph export, affecting relation-filtered queries. The raw extraction and diagnostic warning preserve an audit trail, but do not preserve those facts in the user-facing graph. **Fix:** preserve the validated, canonicalized original relationship list in both exports, using the installed `to_json(..., original_links=...)` facility or an equivalent lossless path. Account for endpoint canonicalization/ghost remaps and legitimate missing external targets; do not pass unvalidated raw endpoints blindly. Verify that both relations on a representative pair remain in exported links after the labels step.

## Accepted correction plan

The controller accepted both findings and proposed a narrow correction. The plan is sufficient: resolve Markdown URLs against their containing document only (absolute in-root references remain exact); keep inline-code resolution separate and require uniqueness. After the normal library build, preserve raw relations only when canonical endpoints exist and the built graph admits their pair, apply the same cross-language/self-import/numeric/path rules, fail on any unresolved referenced declared-node ghost, and audit unresolved undeclared endpoints. Preserve the library's already accepted resolver edges as well, using the directed `(source, target, relation)` fact key rather than only the undirected pair; read true direction from `_src`/`_tgt`. Pass this validated list as `original_links` in both build and label exports.

Use post-build, early-remapped raw IDs: the library mutates semantic/doc remaps in those dictionaries. The installed package exposes no public helper for the complete later `_ghost_remap`/legacy-alias map. `finalize_raw_graph_endpoints` only normalizes IDs and handles external import stubs, so it does not replace the proposed fail-closed identity check. This approves the correction plan, not uninspected implementation or an unexecuted final build. Root owns implementation and final verification.
